## Key Decisions

- **Decision:** Server crontab replaces GitHub scheduled jobs · **Why:** owner asked for GitHub independence · **Alternative considered:** keep GitHub schedules (report history divergence).
- **Decision:** Icon subset generated by a script and guarded by tests, not hand-edited · **Why:** a missing icon would render as an empty box · **Alternative considered:** inline SVG icons (larger template change).
- **Decision:** Card cover variants generated by the existing `make_og_covers.php` · **Why:** the blog skill already runs it for every new article · **Alternative considered:** a separate script (would be forgotten).
- **Decision:** Clarity disclosure text is stored in catalog keys and rendered through `te()` · **Why:** one source for 10 languages and a testable parity with the static Slovak fallback · **Alternative considered:** hard-coded paragraphs in `privacy.php` (the first Clarity commit did that and leaked English text into the other languages).
- **Decision:** Followed the project runbook (commit, push, deploy, verify after each verified change) · **Why:** `.doaudit.md` and `.cursor/rules/always-commit-push-deploy.mdc` require it and the owner asked for a continuing loop · **Alternative considered:** stop at a verified local state as global AGENTS rule 7 says; revisit if the owner objects.
- **Decision:** Handoff is the tracked `HANDOFF.md` plus an untracked session file · **Why:** `/compact` and `/clear` cannot be triggered from inside a session, so these two files make a context reset lossless.
- **Decision:** Compact navigation breakpoint 1320 px, one row above it · **Why:** the longest (Hungarian) labels need that width with a classic scrollbar, and the old 1100 px limit wrapped labels and clipped links · **Alternative considered:** keep 1100 px (what the site had).
- **Decision:** Navbar glass opacity 92 % · **Why:** 91 % is the integer minimum that keeps `--text-muted` at 4.5:1 over a white backdrop in the dark theme, 92 % adds margin (measured 5.03 and 4.70) · **Alternative considered:** 88 % or 90 % (dark theme over white 4.11 and 4.39, below 4.5).
- **Decision:** No site change for a non-deterministic measurement · **Why:** the intermittent `#beatClock` value came from the tool (a 300 ms colour transition after the hide stylesheet is removed), so the tools now wait 700 ms and use computed colours · **Alternative considered:** raising the contrast further (would not have changed the reading).
- **Decision:** The cookie banner height is published by JS as `--cookie-banner-height` (`ResizeObserver`) and consumed by CSS in `scroll-padding-bottom` (plus `--spacing-sm`) and in the footer padding · **Why:** the fixed banner hid the focused element (WCAG 2.4.11) and its height differs by language and window (26 % of a desktop window to 43 % of 390×844) · **Alternative considered:** a fixed pixel padding (wrong in some languages) and a smaller margin (measured, rejected).
- **Decision:** One shared focus ring (`3px solid var(--focus-color)`, offset 2 px) with no per-button outline override · **Why:** the override had the colour of the button surface, so the ring was invisible (1:1 light, 1.05 to 1.26:1 dark); tests check 2 themes × 4 ring/surface pairs · **Alternative considered:** per-surface ring colours (more rules to keep correct).
- **Decision:** The browser-audit toolkit is committed under `scripts/browser-audit/` (not deployed, `node_modules` ignored) · **Why:** Windows may wipe the temp folder where it lived and every loop needs it · **Alternative considered:** keep it in the temp folder.
- **Decision:** Production assets are verified through the versioned URLs found in the HTML · **Why:** the bare `/css/styles.css` is cached upstream with `immutable` and served the previous file after a deploy; every site page uses `?v=` pins, so visitors get the new file.
- **Decision:** One general `@media print` block at the end of `css/styles.css` forces black text on a light scheme with transparent backgrounds, `-webkit-text-fill-color: currentcolor` and `!important` · **Why:** browsers do not print backgrounds, so every colour designed for a dark surface was unreadable on paper, and JS sets `--navbar-height` and `--cookie-banner-height` inline, which only `!important` overrides · **Alternative considered:** per-component print colours (many rules, and a new component would be missed).
- **Decision:** In print the navigation, cookie banner, theme toggle, social links, forms, buttons that are internal links and card cover images are hidden, flash messages stay, the address of external links is printed after the link text, and there is no `@page` rule · **Why:** controls are useless on paper, covers cost pages, a printed link needs its address, and the paper and margins belong to the user's print dialog · **Alternative considered:** printing the forms (admin forms were left untouched).
