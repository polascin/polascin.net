# Opakovaný komplexný audit pre Polascin.net

## Cieľ

Vykonaj opakované behy hĺbkového komplexného auditu dynamickej PHP aplikácie **polascin.net** podľa [`.audit.md`](.audit.md) (bezpečnostný audit OWASP, integrita PHP/HTML/CSS/JS kódu, kvalita databázových dotazov, SEO, responzívny dizajn, prístupnosť WCAG 2.1 AA, GDPR / Google Consent Mode v2, cookie banner a jazyková korektúra) a dodržiavaj bezpečnostné pravidlá uvedené v `.audit.md`.

## Postup

1. Spusti audit podľa kontrolného zoznamu v [`.audit.md`](.audit.md).
2. Zaznamenaj všetky nálezy vrátane ich závažnosti, príčiny a odporúčanej opravy.
3. Implementuj opravy a vylepšenia nájdené v aktuálnom kole.
4. Over zmeny relevantnými projektovými kontrolami:
   - PHP syntax lint: `php -l <file.php>` pre všetky zmenené PHP súbory
   - Databázová inicializácia: `php setup_db.php` (pri zmene schémy; len CLI)
   - Formátovanie a linting: `npx prettier --check css/styles.css js/main.js js/consent-default.js .audit.md .doaudit.md README.md`
   - JS kontrola: `node --check js/main.js && node --check js/consent-default.js`
   - Trunk (ak je dostupný): `trunk check --all --no-progress`
   - Manuálna kontrola HTTP hlavičiek: `curl -I https://polascin.net/`
   - Funkčné testy admin rozhrania, kontaktného formulára a newslettera
5. Zapíš výsledky, vyriešené nálezy a poznatky pre ďalšie behy do [`.audit.md`](.audit.md) (napr. ako nový „Beh #X" s odvolávkami na opravené súbory).
6. Opakuj kroky 1 až 5, kým audit nebude nachádzať žiadne nové bezpečne opraviteľné chyby alebo bugy.

## Bezpečnostné pravidlá

- Nevykonávaj nebezpečné alebo nekompatibilné automatické opravy, napríklad `npm audit fix --force`, bez samostatného posúdenia ich dopadov.
- Známe výnimky a nálezy, ktoré nie je možné bezpečne opraviť, zdokumentuj spolu s odporúčaným ďalším postupom.
- Pri bezpečnostných nálezoch uprednostni obranné riešenia a minimalizuj riziko regresie (CSP, prepared statements, CSRF, rate limiting, session hardening, validácia vstupov).
- Ak sa zmeny týkajú autentifikácie, admin panelu, cookies, kontaktného formulára alebo newslettera, otestuj ich aj manuálne v prehliadači.

### Čo nočný beh robí

1. Overí integritu repozitára a remotu (`git fsck`, `git fetch --all --prune`,
   `main` vs `origin/main`, vetvy, stashe) a otvorené úlohy
   (`gh issue list`, `gh pr list`, `gh run list`).
2. Vykoná beh auditu podľa kontrolného zoznamu v [`.audit.md`](.audit.md).
3. Implementuje **len bezpečné** opravy podľa sekcie „Bezpečnostné pravidlá“.
4. Overí zmeny: `php -l` nad všetkými PHP súbormi, `node --check` nad
   `js/main.js` a `js/consent-default.js`, `npx prettier --check`,
   `php tests/run.php`.
5. Prečíta report z read-only kontroly produkčnej databázy
   [`audit-reports/db-latest.md`](audit-reports/db-latest.md) a jeho nálezy
   zahrnie do behu (viď „Kontrola databázy bez prístupových údajov v cloude“).
6. Commitne a pushne na `main`, počká na GitHub Actions deploy.
7. Overí produkciu: kľúčové URL, 403 na interné súbory, bezpečnostné hlavičky
   a CSP s nonce, zhodu obsahu lokál ↔ produkcia cez SHA-256.
8. Zapíše nový „Beh #X“ do [`.audit.md`](.audit.md) a pushne ho so
   `[skip deploy]`.
9. Odošle e-mailovú správu na `lubomir@polascin.net`.

### Kontrola databázy bez prístupových údajov v cloude

Rutina beží v izolovanom cloudovom prostredí bez SSH na hosting. Databáza je
navyše dosiahnuteľná len lokálne z hostingu (`DB_HOST=localhost`) a heslo k nej
je v `POLASCIN_ENV_INI`, takže **plný SSH kľúč v cloude = produkčné heslo k DB**.
Preto sa credential do cloudu nekopíruje a DB kontroly robí GitHub Actions,
ktorý tie tajomstvá už má a na server už SSH-uje:

| Prvok            | Kde                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------ |
| Workflow         | [`.github/workflows/verify-db.yml`](.github/workflows/verify-db.yml)                       |
| Spúšťanie        | `50 23 * * *` UTC = 01:50 CEST, teda ~12 min pred rutinou; aj `workflow_dispatch`          |
| Kontrolný skript | [`scripts/audit_db_check.php`](scripts/audit_db_check.php)                                 |
| Report           | [`audit-reports/db-latest.md`](audit-reports/db-latest.md) (commitnutý so `[skip deploy]`) |

Skript ide na server po **štandardnom vstupe** (`php` bez argumentov číta kód
zo stdin), takže na hostingu nikdy nevznikne auditný súbor — ani dočasne
dosiahnuteľný z webu. Číta v transakcii `READ ONLY`, spúšťa iba `SELECT`/`SHOW`
a do reportu dáva len agregáty a veky najstarších záznamov, **nikdy** obsah
osobných údajov ani prihlasovacie údaje — report ide do repozitára.

Čo kontroluje: existenciu a engine/collation všetkých tabuliek, aplikované
migrácie proti `setup_db.php`, indexy z migrácie bezpečnostných indexov, počet
aktívnych administrátorov a silu hashov hesiel, duplicitné slugy, jazyky
článkov a obsahových blokov proti `appLanguages()`, a retenciu osobných údajov
(vek najstaršieho záznamu v `access_logs` proti `ACCESS_LOG_RETENTION_DAYS`,
prerezávanie `form_rate_limit`).

Zoznamy zabudované v skripte (tabuľky, migrácie, jazyky) a odvodenie cesty
k `env.ini` v oboch workflowoch stráži `tests/run.php` — keby sa rozišli,
kontrola by hlásila „OK“ na schéme, ktorú nepozná.

Rutina report **iba číta**; nikdy si nevymýšľa stav DB. Ak `Generované:`
v reporte nie je z aktuálnej noci, uvedie to ako nepokrytý rozsah namiesto
prezentovania starých dát ako súčasných.

### Čo nočný beh nepokrýva

Funkčné testy admin prihlásenia, odoslania kontaktného formulára a newsletteru
sa nočne **nevykonávajú** — zapisovali by reálne riadky do produkčnej DB
a posielali reálne e-maily. Patria do manuálneho auditu alebo do staging
prostredia. Rutina nemá prístup ani k lokálnemu stroju zadávateľa; produkcia
sa overuje výhradne cez HTTP (`curl`).

### Povinná štruktúra e-mailovej správy

Predmet: `Nočný audit polascin.net — <dátum> — <stav>`, kde stav je
`OK` / `NÁLEZY` / `ZLYHANIE`.

Telo musí obsahovať:

1. **Súhrn** — jednou vetou výsledok behu.
2. **Nálezy a opravy** — závažnosť, príčina, vykonaná oprava, dotknuté súbory;
   pri nálezoch, ktoré nebolo bezpečné opraviť, odporúčaný ďalší postup.
3. **Výsledok kontrol** — počet prešlých testov, výstup lintov.
4. **Nasadenie a produkčné overenie** — commit SHA, odkaz na beh workflowu,
   HTTP kódy kľúčových URL, stav bezpečnostných hlavičiek.
5. **Stav databázy** — `STATUS` a nálezy z `audit-reports/db-latest.md`
   vrátane času jeho vygenerovania.
6. **Nepokrytý rozsah** — čo cloudový beh overiť nemohol (viď obmedzenia).
7. **Kto a ako audit a verifikáciu deploymentu vykonal** — konkrétne:
   názov a ID rutiny, ID cloudovej session s odkazom na ňu, použitý model,
   prostredie, auditovaný commit, a zoznam skutočne spustených príkazov
   a overených URL. Nie všeobecný opis, ale to, čo v danom behu naozaj bežalo.
8. Podpis `Tvoj AI Agent`.

Ak beh zlyhá alebo sa preruší, správa sa odosiela **aj tak** — s tým, čo sa
stihlo overiť, a s dôvodom zlyhania.

## Dokončenie

Po úspešnom ukončení všetkých auditných kôl **vždy** (bez čakania na ďalší pokyn):

1. Skontroluj finálny diff a stav repozitára (`git status`, `git diff --stat`).
2. Uisti sa, že všetky PHP súbory prechádzajú `php -l` a že CSS/JS sú zformátované.
3. **Commitni** všetky relevantné zmeny s výstižnou správou.
4. **Pushni** commit(y) do `main` (`git push -u origin HEAD` / `git push origin main`). Push do `main` spustí GitHub Actions deploy (pozri [`DEPLOY.md`](DEPLOY.md)); `[skip deploy]` použi len pri čisto dokumentačných doplnkoch po už overenom nasadení.
5. **Over nasadenie** na produkcii:
   - počkaj na úspešný beh workflowu (`gh run list` / `gh run watch`),
   - HTTP odpovede kľúčových URL (`/`, `articles.php`, `contact.php`, `newsletter.php`, `sitemap.php`, `login.php`),
   - interné súbory musia zostať nedostupné (napr. `/deploy_info.php`, `/i18n.php` → 403),
   - bezpečnostné hlavičky a CSP s nonce,
   - funkčné kontroly podľa rozsahu zmien (formulare, admin, cookies).
6. **Zapíš výsledok nasadenia a produkčného overenia** do [`.audit.md`](.audit.md) (do aktuálneho „Beh #X“). Ak ide len o doplnenie tohto záznamu, commitni ho so `[skip deploy]` a pushni na `main`.
