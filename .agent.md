# Polascin Agent – Audit, Security, and Technical Optimization

## Project Overview

**polascin.net** is a static personal website for Dr. Lubomír Polaščín (HTML5 + CSS3 + vanilla JS). It includes:

- Main page (`index.html`) — hero, bio, nephrology, digital products, links hub, contact
- Subpages (`privacy.html`, `terms.html`) — legal documents
- Stylesheet (`css/styles.css`) — custom design with dark mode
- Main script (`js/main.js`) — navigation, dark mode, scroll animations, cookie consent (GA4 Consent Mode v2)
- Server config (`robots.txt`, `.htaccess`) — HTTP headers, scraper blocking
- SEO infrastructure (`sitemap.xml`, JSON-LD, Open Graph, Twitter Card, hreflang)
- FontAwesome 7.1.0 and Google Fonts (local/CDN hybrid)

## Goal

Autonomous agent for comprehensive technical management and continuous optimization of polascin.net. The agent performs in-depth analysis of HTML/CSS/JS code, runs **Trunk** linting and formatting, verifies security configuration (`.htaccess`, HTTP headers), checks SEO integrity and structured data, audits accessibility (WCAG 2.1), responsive design, and performance. It also proofreads English and Slovak text.

## Primary Tasks

### 1. Security Audit

**HTTP security headers in `.htaccess`:**

- Presence and correctness of: `X-Frame-Options`, `X-Content-Type-Options`, `HSTS`, `Referrer-Policy`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`, `X-Permitted-Cross-Domain-Policies`
- `Options -Indexes` — directory listing disabled
- `ServerSignature Off`
- Blocking of `.git/`, `.env`, `*.key`, `*.pem`, `*.sql`, and similar sensitive file patterns

**JavaScript security (`js/main.js`):**

- XSS in dynamic DOM generation (cookie banner, `innerHTML` usage)
- `localStorage` safety — what is stored under `privacy_consent` key and how it is used
- External script loading (Google Analytics) — CSP-compatible loading pattern
- Google Consent Mode v2 implementation — default `denied` state before user interaction

**`.gitignore` check:**

- Protection for `.env`, `*.key`, `*.pem`, `.claude/`
- No sensitive files tracked in git

### 2. HTML Audit

- HTML5 structural validity (`<!doctype html>`, semantic elements)
- `lang="en"` attribute on `<html>`
- Correct nesting and tag closure
- `alt` attributes on all `<img>` elements
- `aria-label`, `aria-hidden`, `role` on interactive elements
- `rel="noopener noreferrer"` on all `target="_blank"` links
- Consistent `id` attributes — no duplicates, anchor targets exist
- Valid email addresses in `mailto:` links

### 3. SEO Optimization

- **Meta tags:** `description`, `keywords`, `author`, `robots`, `theme-color`
- **Robots meta:** `max-image-preview:large` present
- **Canonical URL:** correct and consistent across all pages
- **hreflang:** `en` and `x-default` on all pages; `noindex` on `privacy.html` and `terms.html`
- **Open Graph:** `og:type`, `og:title`, `og:description`, `og:url`, `og:image`, `og:locale`
- **Twitter Card:** `twitter:card`, `twitter:title`, `twitter:description`, `twitter:image`
- **JSON-LD (Schema.org):** `Person` schema validity, completeness of `sameAs` array, correct `jobTitle`, `alumniOf`, `image`
- **sitemap.xml:** up-to-date `lastmod`, correct `changefreq` and `priority`
- **robots.txt:** aggressive scraper blocking, `Crawl-delay`, sitemap reference

### 4. Accessibility (WCAG 2.1)

- Color contrast — light and dark mode (min. 4.5:1 for normal text, 3:1 for large text)
- Keyboard navigation — visible focus, logical tab order
- Skip link (skip to content) — present for screen readers
- `aria-expanded` on the hamburger nav (`navToggle` / `navMenu`) — updated correctly on toggle
- FontAwesome icons — `aria-hidden="true"` plus text alternative
- Cookie banner buttons — `role`, `aria-label`
- Color coding — information not conveyed by color alone
- `prefers-reduced-motion` — animations disabled per system preference (verify in `main.js`)

### 5. Responsive Design

- All `@media` breakpoints in `css/styles.css`
- Content overflow (`overflow-x`) on narrow screens (320px–480px)
- `min-width` values in components — fixed widths causing horizontal scroll
- Hamburger navigation — function and display on mobile
- Hero section, nephrology cards, pill-links, product cards — mobile scaling
- Button size — minimum 44×44 px touch target
- `clamp()`, `vw`, and `auto-fit` grid values

### 6. Performance

- Resource load order — `<link rel="preconnect">` for Google Fonts
- `defer` / `async` on `<script>` tags
- Image sizes — `loading="lazy"` where appropriate
- Cache-busting — CSS version string (`styles.css?v=YYYYMMDD`)
- FontAwesome 7.1.0 — only required icon subsets used
- Google Fonts — `display=swap` present

### 7. Link Integrity

- All external links in `index.html` — logical correctness of `href` values
- Consistency between `sameAs` in JSON-LD and links in the Links section
- Affiliate links (Amazon `amzn.to`, Gumroad) — format, `rel="noopener noreferrer"` present
- Social links in footer (LinkedIn, X, Facebook, Patreon, Discord) — correct URL format
- Internal anchors (`#home`, `#about`, `#nephrology`, etc.) — targets exist in DOM

### 8. Proofreading

- **English texts** — grammar, style, medical terminology (hero, bio, nephrology section, privacy, terms)
- **Slovak texts** — Digital Products section (`Medicínsky pôst`) — grammar, diacritics, style
- Consistent names and titles across all pages
- `<title>` tag format: `Page | Dr. Lubomir Polascin`

### 9. Cookie Consent (GDPR / Consent Mode v2)

- Google Consent Mode v2 default state is `denied` before user interaction
- GA script does not collect data before consent is granted
- Cookie banner text references GA4; Privacy Policy link works
- `localStorage` key `privacy_consent` — values `accepted` / `rejected` are consistent
- `privacy.html` content aligns with GA4 Consent Mode v2 practices

### 10. Trunk — Linting and Formatting

Trunk is configured in [.trunk/trunk.yaml](.trunk/trunk.yaml). The agent runs Trunk commands and interprets their output.

**Configured tools:**

| Tool | Type | What it checks |
| --- | --- | --- |
| `prettier@3.8.3` | Formatting | HTML, CSS, JS, JSON, Markdown — consistent style |
| `markdownlint@0.48.0` | Lint | `.agent.md`, `README.md` — Markdown structure and style |
| `trufflehog@3.95.3` | Security | Secrets and sensitive strings in code and git history |
| `oxipng@10.1.1` | Optimization | Lossless PNG compression (favicons, `CrystalKidney.png`) |
| `svgo@4.0.1` | Optimization | SVG optimization (excludes `fontawesome-free-7.1.0-web/`) |
| `git-diff-check` | Quality | Trailing whitespace, merge-conflict markers |

**Commands:**

```bash
# Check all files (no auto-fix)
trunk check

# Check only files changed since last commit
trunk check --diff

# Auto-format (prettier, oxipng, svgo)
trunk fmt

# Format only changed files
trunk fmt --diff

# Secrets scan only
trunk check --filter=trufflehog

# Markdown only
trunk check --filter=markdownlint
```

**Trunk workflow:**

1. Run `trunk check --diff` on changed files
2. Classify findings by tool: security (trufflehog) → 🔴, formatting (prettier) → 🟢
3. Apply `trunk fmt --diff` automatically (trivial fixes)
4. Trufflehog findings are always 🔴 and **require manual review**
5. Include results in the standard audit report

**Ignored paths (defined in `.trunk/trunk.yaml`):**

- `fontawesome-free-7.1.0-web/` — third-party library
- `websupport-ad-banners-sk/`, `websupport_banners_sk/` — local ad banners

## Auto-Fix Policy

The agent **may fix automatically** without explicit approval:

- Typos and grammar errors in EN/SK text
- Missing `alt` text on `<img>` elements
- Missing `rel="noopener noreferrer"` on `target="_blank"` links
- Inconsistent indentation (whitespace, formatting)
- Missing `aria-hidden="true"` on decorative icons
- Updating `lastmod` in `sitemap.xml`

The agent **must request approval** before:

- Changes to navigation structure or page sections
- Changes to cookie consent logic (`main.js`)
- JSON-LD schema edits (adding or changing fields)
- Changes affecting multiple files simultaneously
- Adding new external dependencies

## Agent Workflow

1. **Initialize:** Load all target files
2. **Trunk check:** `trunk check --diff` — linting, secrets, git-diff-check
3. **Trunk fmt:** `trunk fmt --diff` — auto-formatting (prettier, oxipng, svgo)
4. **HTML audit:** Validity, semantics, attributes, anchors
5. **Security scan:** `.htaccess` headers, JS XSS patterns, `.gitignore`
6. **SEO analysis:** Meta tags, JSON-LD, sitemap, robots.txt, hreflang
7. **Accessibility:** WCAG 2.1 checklist
8. **Responsive design:** Breakpoints, overflow, touch targets
9. **Performance:** Resource loading, lazy loading, cache-busting
10. **Link integrity:** External URLs, anchors, social profiles
11. **Cookie consent:** GA4 Consent Mode v2 compliance
12. **Proofreading:** EN texts; SK texts in Digital Products section
13. **Auto-fix:** Apply trivial fixes and Trunk fmt output
14. **Report:** Results ranked by priority (critical → low)

## Security Constraints

- The agent has **read and write** access for auto-fixing trivial issues
- The agent **does not commit or push** — all changes remain local for review
- Output is **chat-only** — no GitHub Issues or PRs
- The agent respects the exclusions listed in "Excluded from scanning"

## Prohibited and Permitted Actions

**Prohibited:**

- Git commands (commit, push, pull, reset)
- GitHub API operations
- External API calls
- Shell commands (running scripts, deploying)

**Permitted:**

- Reading and writing files
- Static code analysis
- `trunk check` and `trunk fmt` commands
- Auto-fixing trivial issues (including Trunk fmt output)
- Generating reports
